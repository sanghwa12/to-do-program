# F02 · 빠른 입력 + 기본 목록 (쏟아붓기)

## 목적
**이 앱의 존재 이유.** 일하다 떠오른 할 일을 3초 안에 입력하고 바로 일로 복귀할 수 있게 한다.
입력된 할 일은 목록으로 보이고, 완료 체크·수정·삭제가 가능하다.

## 사용자 시나리오
- 일하다 "아 그거 해야지" 떠오름 → 앱 입력창에 한 줄 치고 Enter → 끝. 다시 일하러 감.
- 나중에 앱을 보면 쏟아부은 할 일들이 목록으로 쌓여 있다.
- 끝낸 일은 체크박스로 완료 처리, 잘못 쓴 건 수정하거나 삭제.

## 요구사항 (검증 항목)
- [ ] R1. 화면 상단(또는 눈에 띄는 곳)에 입력창이 있고, **텍스트 입력 + Enter만으로** 할 일이 추가된다.
      (버튼 클릭 필수 ❌, 날짜·우선순위 입력 강요 ❌ — title만으로 저장)
- [ ] R2. 추가 후 입력창이 비워지고 포커스가 유지된다 (연속으로 쏟아붓기 가능).
- [ ] R3. 제목이 비어 있으면 추가되지 않는다.
- [ ] R4. 저장된 할 일 목록이 화면에 렌더링된다 (IndexedDB에서 읽어옴).
- [ ] R5. 완료 체크박스 토글 → `done` 값이 바뀌고 저장되며, 완료 항목은 시각적으로 구분된다 (취소선 등).
      - R5a. **완료 실행취소** (2026-07-03): 체크해서 완료로 바꾸면 "실행취소" 알림이 뜬다.
        오늘 탭·메모판에서는 체크 즉시 항목이 사라지므로, 잘못 눌러도 알림에서 바로 복구.
        (완료→미완료로 푸는 방향은 항목이 사라지지 않으므로 알림 없음)
- [ ] R6. 할 일의 제목/메모를 수정하고 저장하면 반영된다.
- [ ] R7. 삭제 버튼으로 지울 수 있고 IndexedDB에서도 제거된다.
      - R7a. 삭제는 곧바로 실행하지 않고 **한 번 더 확인**한다 (그 자리에서 "삭제할까요? 삭제/취소").
      - R7b. 삭제 후 **되돌리기**를 제공한다 (화면 아래 알림. 시간 제한 없이,
        되돌리기 또는 닫기(✕)를 누를 때까지 유지. 원래 그대로 복구).
      - R7c. **일괄 삭제**(전체 삭제, 카테고리별 삭제)도 확인 + 실행취소를 지원한다 (2026-07-03).
      - R7d. **휴지통**(2026-07-03): "삭제"는 진짜로 지우지 않고 휴지통으로 보낸다(`deletedAt` 기록).
        목록에선 사라지지만 데이터는 남아, 휴지통 화면에서 **복원**하거나 **완전 삭제**할 수 있다.
        "휴지통 비우기"로 전체 완전 삭제(확인 필요). 완전 삭제만 되돌릴 수 없다.
- [ ] R8. 새로고침 후에도 위 변경(추가/수정/삭제/완료)이 그대로 유지된다.
- [ ] R9. **날짜 자동 인식 — 3가지 종류** (2026-07-02 추가·확장):
      날짜 표기를 인식해 저장하고, 그 표기는 제목에서 뺀다. 표기가 없으면 날짜 없는 할 일.
      | 종류 | 표기 | 입력 예 | 저장 결과 |
      |------|------|---------|-----------|
      | 마감(due) | `~날짜` (어디든) | `도서 반납 (~7/2)` | 제목 "도서 반납" + 7/2까지 |
      | 당일(day) | 맨 날짜 (**문장 끝만**) | `연구실 안전점검 7/7` | 제목 "연구실 안전점검" + 7/7 당일 |
      | 기간(range) | `날짜~날짜` (어디든) | `학부실험 조교 11/11~11/23` | 제목 + 11/11부터 11/23까지 |
      - 비인식 예: `보고서 초안쓰기` → 날짜 없음 (날짜 강요 ❌)

      Enter 치기 전에 확인할 수 있다 (예: "📅 7/2까지 마감으로 저장됩니다").
- [ ] R12. **여러 줄 가져오기(붙여넣기)**: 여러 줄 텍스트를 붙여넣으면 줄마다 할 일로 저장한다.
      - 각 줄에 날짜 자동 인식(R9~R11)과 `#태그`→카테고리 인식을 적용한다.
      - `- [ ]`(미완료) / `- [x]`(완료) 앞머리를 인식한다 (내보내기 형식과 호환 → 왕복 가능).
      - `#`으로 시작하는 줄과 빈 줄은 무시한다 (주석·섹션 제목).
      - 넣기 전에 "N개 추가됩니다" 미리보기를 보여준다.
      - **같은 "제목+완료상태"가 이미 목록(휴지통 제외)에 있으면 건너뛰고 개수를 알려준다**
        (같은 파일 이중 가져오기 사고 방지 — 2026-07-03 추가.
        완료상태까지 비교하는 이유: 반복 할 일(F09)은 같은 제목의 완료 기록이 정상적으로
        여러 개 생기므로 — 2026-07-06 개선).
      - 백업 파일의 **공지 줄(📢로 시작)은 건너뛴다** — 공지가 할 일로 둔갑하지 않게
        (공지 복원 방법은 F08 미결정 — 2026-07-03 추가).
      - **기간의 예외 날짜** `➖제외한 날들 ➕추가한 날들`을 읽어 복원한다 (2026-09-28, F03 R9 ·
        F06 R6). 기간이 아닌 줄에 붙어 있으면 무시, 범위를 벗어난 날짜는 정리된다.
- [ ] R14. **등록 시 날짜 있음/없음 구분** (2026-07-09 추가):
      - 입력줄 옆 **📅 버튼** → 날짜 선택기. 고른 날짜는 마감(due)으로 등록
        (표기를 몰라도 날짜 있는 할 일을 등록할 수 있게).
      - 입력 중 미리보기가 두 종류를 **항상 구분해** 보여줌:
        파랑 "📅 …로 저장됩니다" / 회색 "날짜 없는 할 일로 저장됩니다".
      - 텍스트 표기(~7/2, 7/7, 매주 등)가 있으면 **표기가 우선** (선택기 무시).
      - 등록하면 텍스트와 날짜 선택 모두 초기화 (다음 입력은 다시 기본 = 날짜 없음).
      - 단, 📅는 어디까지나 선택 — 기본 흐름(제목+Enter)의 속도는 그대로 (핵심 원칙).
- [ ] R15. **시간 인식** (2026-09-07 추가, 사용자 요청 — "9/7 14:00으로 쓰면 14시로"):
      날짜 표기 **바로 뒤에** 시간을 쓰면 같이 저장. 선택 사항 — 안 쓰면 날짜만.
      - 표기: `14:00` · `14시` · `14시 30분` (24시간). 마감·당일 모두 가능
        (`~9/7 14:00`, `안전점검 9/7 14:00`). 기간(`9/7~9/9`)에는 시간 없음.
      - 저장: `dueTime`("HH:MM"). `dueDate`는 그대로 날짜만 → 오늘·달력·밀림 규칙 불변.
      - 표시: 날짜 뱃지 끝에 시간(`📅 9/7 당일 14:00`), 달력 칩 앞에 시간.
        같은 날짜끼리는 시간 순, 시간 없는 것은 뒤.
        (2026-09-28 버그 수정: 실제로는 시간 없는 것이 **앞**에 오고 있었음 — 비교에 쓴
        `localeCompare`가 기호 "~"를 숫자보다 앞에 놓기 때문. 글자 코드 순 비교로 교체)
      - 미리보기·수정 화면(시간 칸)·백업 왕복(`📅 ~2026-09-07 14:00`) 지원.
- [ ] R16. **종류 토글 [☑ 할 일] [📢 일정]** (2026-09-28 추가, 사용자 요청 — "맨 위 입력칸에
      할 일뿐 아니라 일정도 입력, 선택할 수 있게"):
      - 입력칸 왼쪽의 토글. **기본은 할 일** — 안 건드리면 기존 흐름(제목+Enter)과 속도 그대로.
      - 고른 쪽은 진한 테두리로 표시: 할 일 = 파랑, 일정 = 보라 (같은 굵기·세기).
        버튼 글자색은 어느 쪽이든 검은색 그대로. 일정을 고른 동안에는 **입력칸의 포커스
        테두리와 📅 버튼의 선택 테두리도 보라** (파랑은 할 일일 때만).
        할 일 앞에는 **파란 체크 아이콘**(앱 아이콘과 같은 파란 네모+흰 체크, CSS로 그림 —
        초록 ✅ 이모지는 사용자 비선호), 일정 앞에는 📢 (사용자 요청 2026-09-28).
      - **일정**을 고르면 체크 없는 일정(날짜 있는 노트, F11)으로 저장 (`addMemo`).
        인식 규칙은 노트 입력줄과 같음: 지난 날짜 그대로, 반복 인식 없음.
        날짜는 텍스트 표기 우선, 없으면 📅로 고른 날짜. 둘 다 없으면 날짜 없는 노트로 저장.
      - 고른 종류는 **바꿀 때까지 유지** (일정 연속 입력). 앱을 다시 켜면 할 일로 돌아옴.
      - 토글을 눌러도 커서는 입력칸으로 돌아온다 (바로 이어서 타이핑).
      - 미리보기: 일정이면 보라색 "📢 날짜 일정으로 저장됩니다", 날짜가 없으면 회색
        "날짜가 없어 📝 노트로 저장됩니다". 기간·시간도 그대로 저장되고 미리보기에 표시
        (`📢 2026-10-06 ~ 2026-10-16`, `📢 2026-10-01 14:00` — F11 R8).
      - 할 일을 고른 상태의 당일 미리보기는 "당일 **할 일**로 저장됩니다" (예전 문구
        "당일 일정"은 📢 일정과 헷갈려서 바꿈).
- [ ] R17. **`~이번주` 표기** (2026-10-26 기획, 사용자 요청 — "이번 주에 ~ 이런 일을 하고 싶어서"):
      `보고서 정리 ~이번주` → 요일을 정하지 않은 **"이번 주 중에" 할 일**로 저장 (F03 R10).
      - 인식: `~이번주` / `~이번 주` (괄호 `(~이번주)`도). 문장 어디에 있어도 되고 표기는 제목에서 뺀다.
        `~` 없이 `이번주`만 쓰면 인식하지 않음 — `이번주 회의 준비` 같은 제목이 바뀌지 않게.
      - 미리보기: "🗓 이번 주(10/26~11/1) 안에 할 일로 저장됩니다".
      - 인식하는 곳: 맨 위 입력칸(할 일), 달력 날짜 칸의 입력(할 일 — 텍스트 표기 우선 규칙대로).
        **📢 일정 입력에서는 인식하지 않음** (일정엔 "이번 주 중에"라는 개념이 없음 — 글자 그대로 남음).
      - 반복 표기와 함께 쓰면 반복이 우선 (기간과 같은 규칙).
      - 표기는 `~이번주` 하나만 (사용자 결정 — `~다음주` 등은 만들지 않음).
- [ ] R18. **붙여 넣은 여러 날짜 형식 인식** (2026-11-16, 사용자 요청 — "다양한 날짜나 시간을
      붙여 넣어도 알아서 입력되게"). 메일·공지에서 복사한 글의 날짜를 그대로 알아듣는다.
      기본 표기(R9~R11·R15)로 안 잡힐 때만 적용 — 예전 입력의 결과는 바뀌지 않는다.
      - **확실한 날짜는 문장 어디에 있어도**: 연도가 있는 숫자 날짜(`2026-11-30` · `2026/09/30` ·
        `2026. 11. 30.`), 한글 날짜(`2026년 9월 15일` · `26년 9월 15일` · `11월 30일`).
      - **짧은 표기**(`11/30` · `11.30`)는 뒤에 요일·시간·`까지/마감`이 붙었을 때만 문장 앞·가운데에서도
        인식 (`11/30(월) 14:00 세미나`). 그냥 `3/4 분량 읽기`는 지금처럼 제목.
      - **요일**: `(화)` · `(화요일)` · `화요일` — 읽고 버림 (날짜가 기준).
      - **시간**: `오전 8시` · `오후 2시 30분` · `오후 2:30` · `8시 반` · `2:00 PM` · `10:00:00`.
        **끝 시간은 버린다** (`10:00 ~ 11:00` → 10:00. 사용자 결정 "가볍게 시작시간만" — 끝 시간 칸은 만들지 않음).
        `2시간`(걸리는 시간)은 시간으로 보지 않음. `3시`는 쓴 그대로 03:00 (오전·오후 추측 안 함).
      - **마감으로 보는 것**: 앞에 `~`, 뒤에 `까지`·`마감` (`11월 30일까지`, `(11.30 마감)`,
        `(1106일마감)` — 붙여 쓴 네 자리는 `일마감/일까지`가 있을 때만). 그 밖에는 당일.
        날짜에 붙은 `부터`·`에`는 같이 뺀다 (`13:00부터`).
      - **기간**: `2026. 11. 16.(월) ~ 11. 20.(금)` · `11월 16일부터 20일까지` · `12.3(목)-12.5(토)` —
        끝 날짜에 연도·월이 없으면 시작 날짜 것을 따름. 기간엔 시간 없음(R15와 동일).
      - 날짜를 감싼 괄호는 같이 빼고, 제목이 비면 인식하지 않는다 (기존 규칙).
      - 연도 없는 지난 날짜는 기존 규칙대로 내년으로 (일정 입력은 올해 그대로) — 미리보기에 연도가 보임.
      - 적용되는 곳: 인식 함수를 쓰는 모든 입력 (맨 위 입력칸 할 일·일정, 달력 입력, 노트 입력, 가져오기).
      - 범위 밖: 끝 시간 저장, `~` 없는 말 날짜(`내일 오후 3시`), 두 자리 연도 숫자 날짜(`26.11.30`).

      - 기간: 연도를 생략했을 때만 보정한다 — 끝이 시작보다 빠르면 해를 넘는 것(`12/28~1/3`),
        통째로 지났으면 내년. **연도를 직접 적은 기간은 적은 대로** (2026-09-28 수정 — 백업 파일의
        지난 기간 `2026-09-01 ~ 2026-09-05`가 가져올 때 내년으로 밀리던 버그).
      - 말 날짜(마감 `~`에서만): `~오늘`, `~내일`, `~모레`, `~월요일`~`~일요일`
        (요일은 다가오는 그 요일. 오늘이 그 요일이면 오늘)
      - 당일(맨 날짜)을 문장 끝에서만 인식하는 이유: `3/4 분량 읽기` 같은
        분수 표현을 날짜로 오인하지 않기 위해서.
      - 존재하지 않는 날짜(예: `~13/40`)는 무시하고 전체를 제목으로 저장.
