# F12 · 구글 캘린더로 보내기

> 2026-09-10 조사(에이전트 9개, 주장 105개 중 103개 공식 문서로 확인) 뒤 사용자 결정:
> **A안 — 서버 없이 브라우저에서 구글 API 직접 연결, 앱 전용 보조 달력, 한 방향(push).**
> 조사 경위와 대안 비교는 `작업노트.md` 2026-09-10 항목.

## 목적
앱에 날짜를 붙여 둔 할 일·일정 노트를 **구글 캘린더에도 똑같이 보이게** 한다.
구글이 알아서 폰에도 보여 주므로, 폰 연동을 따로 만들지 않고도 밖에서 일정을 확인할 수 있다.

## 핵심 결정 (사용자 선택, 2026-09-10)
- **방식**: 브라우저가 구글에서 1시간짜리 임시 출입증(액세스 토큰)을 팝업으로 받아
  캘린더 API를 직접 부른다 (Google Identity Services 토큰 모델 + Calendar API v3).
  우리 서버·클라우드 DB 없음. 구글 클라우드 "프로젝트"는 만들지만 이건 OAuth **등록증**일 뿐
  (서버·DB·함수를 돌리지 않음 — 클라우드 백엔드 금지 원칙과 충돌하지 않는다고 해석).
- **대상 달력**: 앱이 만드는 **보조 달력 "My planner"** (2026-09-28 앱 이름 변경 — 그 전에
  만든 달력은 구글에서 이름을 바꾸기 전까지 "할 일 앱". 앱은 id로 찾으므로 이름과 무관) 하나만. 권한도 "앱이 만든 달력만"
  (`calendar.app.created`) — 기본 달력엔 손댈 수 없어 실수해도 이 달력만 지우면 끝.
- **방향**: **앱 → 구글 한 방향.** 구글에서 고친 내용은 앱으로 오지 않고, 다음 보내기 때
  앱 내용으로 덮어씌워진다 (도움말에 명시).
- **보낼 것 = 앱 달력 탭에 보이는 것 그대로.** 완료 여부는 신경 쓰지 않는다
  (사용자: "달력에 있는 것만 넣고 싶어서 완료 여부는 중요하지 않아") →
  완료해도 이벤트는 그대로, ✓ 표시나 삭제 없음.

## 데이터 → 이벤트 매핑
| 앱 데이터 | 구글 이벤트 |
|---|---|
| 당일 `7/7` / 마감 `~7/2` (시간 없음) | 그날 **종일** 이벤트 (`start.date`, `end.date` = 다음날) |
| 시간 있음 `9/7 14:00` (F02 R15) | 그 시각부터 **60분** 이벤트 (앱에 길이 개념이 없어 기본값) |
| 기간 `11/11~11/23` | 시작~끝 **종일** 이벤트 (`end.date` = 끝 다음날) |
| 기간 + 예외 날짜 (F03 R9, 2026-09-28) | 이어진 날끼리 **조각**으로 나눠 조각마다 종일 이벤트 하나 — `10/6~10/16`, 10/9 제외, 10/19 추가 → `10/6~8` · `10/10~16` · `10/19` 3개 (구글 이벤트 하나로는 "중간에 빠진 날"을 못 나타냄). 일정(📢)도 같음 |
| 반복 할 일 | 1차: **현재 회차 1건**만 (RRULE 변환은 2차) |
| 일정 = 날짜 있는 노트 (📢) | 제목 앞 `📢 ` + 첫 줄, 종일 이벤트 |
| 일정 — 기간 / 시간 (F11 R8, 2026-09-28) | 기간: 시작~끝 **종일**, 시간: 그 시각부터 **60분** (할 일과 같은 규칙) |
| 날짜 없는 메모판 할 일 | 보내지 않음 (구글엔 날짜 없는 이벤트가 없음) |
| 휴지통 / 날짜 제거 / 노트 삭제 | 구글 이벤트 **삭제** ("달력에서 빠지면 빠진다") |

## 요구사항 (검증 항목)
- [ ] R1. **설정 화면**: ⋯ 메뉴에 "📆 구글 달력" 항목. 화면에 ① 클라이언트 ID 입력칸
      (1회 입력 → IndexedDB `settings`에 저장, 코드·깃에 남지 않음) ② "구글 연결" 버튼
      ③ "지금 보내기" 버튼 ④ 마지막 보낸 시각 / 마지막 오류 한 줄.
- [ ] R2. **연결**: "구글 연결"을 누르면 GIS 라이브러리를 그때 불러와(정적 태그 ❌ —
      오프라인 PWA에서 깨지지 않게) 팝업으로 토큰을 받는다. 토큰은 **메모리에만** 두고
      응답의 `expires_in`으로 만료를 계산한다 (3600 고정 ❌). 오프라인이면 버튼 대신
      "오프라인 — 인터넷 연결 후 다시" 안내.
- [ ] R3. **보조 달력**: 첫 보내기 때 `calendars.insert`로 "My planner" 달력을 만들고 id를
      settings에 저장. 이후엔 이 id만 사용. 사용자가 구글에서 그 달력을 지웠으면(404)
      다시 만들고 링크 표를 비운다.
- [ ] R4. **보내기(한 방향)**: "지금 보내기"를 누르면 (출입증이 없거나 만료면 먼저 연결 팝업으로
      받고 — 2026-09-10 보완) 대상 집합(날짜 있는 할 일 전부(휴지통 제외)
      + 날짜 있는 노트)을 계산해 —
      - 링크 없는 항목 → `events.insert` (앱 id를 `extendedProperties.private.todoId`에 기록)
      - 링크 있고 내용이 바뀐 항목 → `events.update`(통째 교체 — patch는 종일↔시간 전환 시
        date/dateTime이 겹쳐 실패할 수 있음) (내용 지문 비교, 안 바뀌면 호출 없음)
      - 링크는 있는데 대상에서 빠진 항목 → `events.delete` 후 링크 제거
      - 진행 중엔 버튼 비활성 + "보내는 중 n/m", 끝나면 "보냄 n건 · 삭제 k건 · HH:MM".
- [ ] R5. **입력 경로 무변경**: 한 줄 입력(QuickInput)·저장 함수는 손대지 않는다.
      보내기는 버튼을 눌렀을 때만 (1차) — 자동 보내기는 2차 검토.
- [ ] R6. **실패 처리**: 401(토큰 만료)이면 출입증을 버리고 안내만(다음 "지금 보내기"가 다시 받음),
      앱은 계속 동작.
      그 밖의 오류는 settings.lastError에 한 줄 기록 + 설정 화면에 표시. 화면을 막는
      alert ❌. 부분 실패해도 이미 보낸 링크는 유지.
- [ ] R7. **데이터**: Dexie version 8 — `settings`("key": clientId · calendarId · lastSyncAt ·
      lastError) + `gcalLinks`("localId, eventId": localId(할 일 id 또는 "memo:"+노트 id),
      eventId, hash). tasks·memos·boards 테이블은 무변경.
      예외 날짜가 있는 기간은 조각마다 한 줄 — localId 뒤에 `#0`, `#1`…을 붙여 구분 (2026-09-28).
      예외가 없는 항목의 localId·지문은 예전과 같아서, 이미 올린 이벤트가 다시 올라가지 않는다.
      예외를 새로 넣거나 없애면 다음 보내기 때 옛 이벤트 삭제 + 새 이벤트 추가로 반영 (R4 규칙 그대로).
- [ ] R8. **백업 왕복 영향 없음**: 내보내기/가져오기 형식 불변. 가져오기로 id가 새로 생기면

## 구글 클라우드 설정 절차 (사용자가 직접, 10단계 — 무료, 카드 등록 없음)
1. https://console.cloud.google.com 접속 (개인 Gmail) → 상단 프로젝트 선택 → **새 프로젝트**
   → 이름 `todo-calendar` → 만들기. "무료 체험/결제" 안내가 뜨면 **건너뜀**.
2. 왼쪽 **API 및 서비스 → 라이브러리** → `Google Calendar API` 검색 → **사용**.
3. **Google Auth Platform → 개요 → 시작하기**: 앱 이름 `My planner`(팝업에 보이는 표시용 이름 — 처음엔 `할 일`로 등록함, 브랜딩 메뉴에서 변경 가능), 지원 이메일 = 본인
   Gmail, 대상(Audience) = **외부(External)**, 연락처 = 본인 Gmail → 만들기.
   게시 상태는 **테스트(Testing)** 그대로 둠 (프로덕션으로 올리지 않음 — 검증 불필요).
4. **Google Auth Platform → 대상(Audience) → 테스트 사용자 → + Add users** → 본인 Gmail 추가.
5. **Google Auth Platform → 데이터 액세스(Data Access) → 범위 추가** →
   `https://www.googleapis.com/auth/calendar.app.created` 하나만 체크 → 업데이트 → 저장.
6. **Google Auth Platform → 클라이언트(Clients) → 클라이언트 만들기** → 유형 **웹 애플리케이션**
   → 이름 `todo-app` → **승인된 JavaScript 원본**에 `http://localhost` 와
   `http://localhost:5173` 두 줄 추가 → 리디렉션 URI는 비움 → 만들기.
7. 표시되는 **클라이언트 ID**(`…apps.googleusercontent.com`)를 복사해 둠.
   "클라이언트 보안 비밀번호"는 브라우저 앱에서 쓰지 않으니 **무시** (어디에도 저장 ❌).
8. 앱의 ⋯ 메뉴 → 📆 구글 달력 → 클라이언트 ID 붙여넣기 → 저장 (구현 후).
9. "구글 연결" → 팝업에서 계정 선택 → "Google에서 확인하지 않은 앱" 경고에서 **계속**
   → 권한 허용. (7일마다 이 화면이 다시 나오는 게 정상.)
10. "지금 보내기" → https://calendar.google.com 왼쪽 목록에 **"My planner"** 달력이 생기고
    일정이 보이는지 확인. 폰에서 안 보이면 폰 캘린더 앱 → 더보기 → 해당 달력 동기화 켜기.

## 감수하기로 한 것 (사용자 동의 2026-09-10)
- 1시간마다 출입증을 새로 받아야 함 — "지금 보내기" 클릭에 흡수(팝업 잠깐, 2026-09-10 보완).
  완전 자동 갱신은 서버가 받는 refresh token이 필요해 불가. 앱이 꺼져 있으면 보내기 불가.
- 7일마다 "Google에서 확인하지 않은 앱" 경고 + 동의 화면 (영구 "테스트" 상태의 대가).
- 보안 모범 사례가 권하는 "코드 플로우"는 서버가 필요해 못 쓰고 브라우저 토큰 방식을 씀 —
  1인용·localhost 원본 한정이라 실질 위험은 낮다고 판단.
- 구글에 올린 일정은 같은 계정의 폰 구글 캘린더에도 보임 (컴퓨터 전용 원칙의 예외가 아니라
  부수 효과 — 원하면 폰에서 그 달력을 숨기면 됨).
- 6개월 이상 안 쓰면 구글이 클라이언트를 자동 삭제 (30일 전 메일) → 다시 설정.

## 관련 제약 (CLAUDE.md)
- 서버·클라우드 백엔드 금지 → 브라우저 fetch만. 구글 클라우드 프로젝트는 등록증 역할.
- 비용 0 → 결제 계정 미연결, Calendar API 표준 사용 무료 (1인 사용량은 과금 임계값의 1% 미만).
- 시크릿 하드코딩 금지 → 클라이언트 ID는 공개값(RFC 6749 §2.2)이지만 설정 화면 입력 →
  IndexedDB 저장으로 코드·깃에 남기지 않음. 보안 비밀번호는 사용 자체를 안 함.
- 입력 마찰 최소화 → 입력·저장 경로 무변경 (R5).
- IndexedDB → settings·gcalLinks도 IndexedDB. 토큰은 저장하지 않음(메모리).
