## 2026-08-05 · 메모판 바로 수정 + 카테고리 기능 정리
- **메모판(노란 판) 바로 수정**: 글자 클릭 → 그 자리 편집 (Enter 저장, Esc 취소).
  "수정은 전체 탭에서"라는 우회가 사라짐.
- **카테고리 UI 완전 정리 (사용자 결정)**: 수정 화면의 카테고리 입력칸·목록의 #뱃지 제거.
  카테고리 탭 제거(8/3)의 후속 — 화면에서만 제거, **저장된 category 데이터는 보존**
  (update 객체에서 제외하는 방식). 가져오기의 #태그 인식도 데이터 수준에선 유지(백업 호환).

## 2026-08-04 · 계획 미루기 + 기록 보존 원칙
- 하루 탭 미완료 계획에 미루기 추가: **내일로 / 날짜… / 메모로**(=날짜 없는 할 일 → 노란 판)
  + "미완료 N개 모두 내일로" 일괄.
- **기록 보존 원칙 (사용자 지적)**: 미룬 계획은 원래 날짜에 "→ 어디로 미룸" 표시로 남아
  계획 총 개수가 변하지 않음 — 미루기로 달성률을 조작할 수 없게. 이 원칙은 하루 기록의
  정직성(계획 vs 실제 거울)의 핵심이므로 앞으로의 기능에도 적용할 것.

## 2026-08-03 · 대통합: 알아둘 것 + 노트 → 하나의 "노트" (A안)

- 지킨 것: "할 일(체크) vs 노트(체크 없음)" 근간 구분 — 노란 메모판은 그대로.

## 2026-08-03 · 핵심 가치 재확인 + "항상 위 스티커 창(B안)" 기각
- 사용자가 밝힌 최우선 가치 2가지:
  ① 스티커 메모처럼 손쉽게 열어 확인 (단, **항상 떠 있으면 오히려 방해** — 작업 화면을 가리면 안 됨)
  ② 기한 있는 일 / 없는 일을 구분해 기록·확인 (→ 현재 구조가 이미 충족)
- 따라서 ①의 답은 **PWA 설치 마무리(F05)** = 앱 아이콘으로 한 클릭 실행.
  평가보고서에 대기 중이던 "항상 위 스티커 창(B안)"은 **하지 않기로 확정**.
- 합의된 순서: **자동 백업(최대 리스크 제거) → PWA 마무리(핵심 가치 ①) → 검색**.
  신규 기능은 그때까지 동결 (2026-08-03 평가보고서 권고 채택).

## 2026-07-03 · 서비스 워커 캐시 문제 → 개발 중 self-destroying로 전환
- **문제**: 코드를 고쳐도 설치된 앱(localhost:4173)이 옛 버전에 갇혀 최신 기능이 안 보임.
  F5 새로고침도 안 먹힘. PWA 서비스 워커가 옛 화면을 캐시로 붙잡고 있어서 생긴 일.
  이 때문에 "가져오기" 기능이 있는데도 앱에는 안 보이고, 옛 코드로 가져오기가 되어
  `[x]`가 제목에 남고 `#` 안내문 줄까지 할 일로 들어가는 등 오작동.
- **결정**: `vite.config.js`의 VitePWA를 **`selfDestroying: true`** 로 변경.
  서비스 워커가 자기 자신을 지우고 캐시를 비움 → 개발 중 항상 최신 코드가 뜨게 됨.
  (오프라인 기능은 잠시 꺼짐. 앱이 안정되면 false로 되돌려 다시 켠다.)
- **개발 워크플로 확정**:
  - 개발/테스트는 **개발 서버 `npm run dev` (localhost:5173)** 에서. SW가 없어 F5가 바로 먹힘.
  - 설치형 앱(4173)은 **모든 기능이 안정된 뒤 마지막에** 다시 설치.
    데이터 이전은 우리가 만든 **내보내기 → 가져오기**로 처리 (origin이 달라 자동 이전은 안 됨).
