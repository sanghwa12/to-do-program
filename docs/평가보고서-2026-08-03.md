- **작성일**: 2026-08-03
- **작성**: Claude (사용자 요청: "지금까지 진행한 내용을 비판적으로 평가 + 투자자라면 투자하겠는가")
- **시점 배경**: 마일스톤 1~3 완료, F11 메모장까지 구현된 상태.
  "스티커 메모 모드(F12)" 방안 선택(1단계)이 대기 중인 시점의 평가.

## 한 줄 결론

**투자 상품으로는 투자 불가. 그러나 애초에 투자 상품이 아니며,
개인 도구의 성공 기준(매일 쓰는가)으로는 이미 흑자.**
계속 투자(시간)할 가치가 있되, 우선순위 조건 3가지를 걸 것.

## 아픈 지점 5가지

### ① 기능이 "사용 검증"보다 빨리 늘고 있다
"3초 입력 할 일 앱"으로 시작해 공지 → 달력 → 하루 기록 → 메모장으로 확장.
**이미 만든 기능을 실제로 매일 쓰는지 검증한 적이 없다** (예: 하루 기록을 매일 채우는가?).
안 쓰는 기능은 관리비 나가는 빈 방. D00 기획서 스스로 "탭이 많다고 느껴지면
재검토 신호"라고 적어둔 상태 — 그 신호에 가까워지는 중.

### ② 데이터는 소중해지는데 안전장치는 수동 ★최대 리스크
전 데이터가 크롬 프로필 하나의 IndexedDB에 있음. "인터넷 사용 기록 삭제" 한 번,
프로필 초기화 한 번에 전멸 가능. 백업은 사람이 기억해서 눌러야 함.
4173/5173 이중 저장소 혼선(주소가 다르면 금고가 갈라짐)이 이 구조의 취약성을 보여준 사례.
**이 프로젝트의 최대 리스크는 기능 부족이 아니라 데이터 유실.**

### ③ 기반이 "개발용 모드"로 상시 운영 중
매일 쓰는 앱이 개발용 서버(`npm run dev`)로 돌아감. node 서버 + 크롬 + localhost
세 가지가 모두 살아 있어야 작동. 정식 설치형(PWA, F05)은 캐시 문제로 보류 상태.
비유: 가건물에서 잘 살고 있는 셈.

### ④ 넣는 문은 많은데 찾는 문이 없다
5종 데이터를 부을 수는 있으나 검색이 없어 찾는 방법이 스크롤뿐.
2026-07-22 메이저 앱 비교 리포트에서도 1순위 공백으로 지목됨.

### ⑤ 유지보수 버스팩터 = Claude
개발자(사용자)는 코드를 읽지 못함 → 장애 시 자력 복구 불가.
특히 한국어 날짜 인식(parse.js)은 과거 검증에서 버그 10건이 나온 복잡 부품.
다만 기획서 + 작업노트 + spec-check 규율이 이를 상당히 방어 중 (취미 프로젝트에서 드문 수준).

### (덤) 프로세스 반성
2026-07-30 세션에서 Claude가 단계 확인 없이 제안서+구현까지 진행 → 전체 되돌림.
프로그램이 아닌 진행 방식의 문제였고, 재발 방지 기록됨 (단계마다 멈추고 확인).

## 잘한 것

- **입력 마찰 원칙을 한 번도 팔지 않음** — 기능이 늘어도 입력은 "한 줄 + Enter" 유지. 이 앱의 척추.
- **사고에서 배운 안전장치** — 중복 가져오기 사고(7/3) 이후 중복 방지, 휴지통,
  모든 삭제에 확인+실행취소. 안전장치가 실제 사고 이력에서 자람.
- **비용 0원 · 데이터 인질 없음** — .md 백업(Obsidian 호환)으로 탈출구 확보.
- **문서 규율** — 기능마다 기획서, 결정마다 작업노트, spec-check 대조 체계.

## 투자자 관점 분석

**사업 투자: 불가.**
- 할 일 앱 시장은 포화 (무료 강자 MS To Do·Google Tasks, 유료 Todoist도 성장 정체).
- 차별점(한국어 자연어, 로컬 소유, 계획vs실제)은 기능이지 해자(moat)가 아님.
- 결정적으로, 상업적 성장에 필요한 것들(동기화·협업·클라우드)을 **일부러 거부하는 설계**.
  1인용·로컬·0원 — 성장하지 않기로 구조부터 정해진 제품.

**그러나 이 프로그램의 투자자는 이미 존재 — 사용자 본인.**
- 투자금 = 시간 (금전 0원). 배당 = ① 윈도우 스티커 메모 37개 실제 이전 완료,
  ② 부팅 시 자동 시작으로 일상 편입, ③ 시장에 없는 조합(한국어 자연어 + 로컬 소유 +
  행정 도우미 + 계획/실제 일기)이 본인 업무 방식에 100% 맞춤.
- **개인 도구의 성공 기준(매일 쓰는가)으로는 이미 흑자.**

## 권고: 다음 라운드 조건 3가지

1. **신규 기능 동결, "자동 백업"부터** — 앱을 열 때마다 자동으로 백업이 남게.
   최대 리스크(②) 제거가 최우선. 서버 없이 구현 가능.
2. **그다음 검색** — 이미 부은 것을 찾을 수 있게 (④ 해소).
3. **안 쓰는 기능 하나 정리** — "2주간 안 쓴 탭은 숨김 후보" 같은 사용 검증 습관 (① 해소).

대기 중인 스티커 메모 건에 대한 의견: **D(`메모:` 빠른 입력)는 작아서 언제든 병행 가능,
B(항상 위 스티커 창)는 자동 백업·검색 뒤가 합리적.** 최종 결정은 사용자 몫.
